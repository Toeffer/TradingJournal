## Data integrity — defect found in `data/eu_quote_history.csv`

This is the most actionable finding of the run and it affects any future setup built on EU data.

The EU history writer mislabels sessions when a scan runs outside market hours, and it happened this week:

- **Duplicated sessions.** Thursday 2026-08-27's bar was written again under Friday 2026-08-28 for 46 of 46 tickers — identical high, low and close. The same fault occurred once before, on 2026-07-03 → 2026-07-04 (45 tickers). These are the only two occurrences in 169 days.
- **Weekend-dated rows.** Both incidents produced a row dated on a Saturday (2026-07-04 and 2026-08-29) when XETRA is closed. The Saturday-dated row actually carries the *real* last session — the scan ran at 02:04 CEST on Saturday and stamped Friday's completed session with the run date.
- **Impossible bars.** 50 rows in the file have an `open` outside their own `[low, high]` range. All 50 fall on 2026-08-28 (21) and 2026-08-29 (29). BMW.DE's Friday row reads open €57.50 against a low of €60.38; the `open` field is stale, carried from the prior session, while high/low/close reflect the newer one. The rest of the file is clean: 1 bad close in 7,767 rows.

Net effect: the two most recent rows — precisely the ones any current-week setup would be built from — are the corrupted ones, and a naive read of the file overstates the session count, distorts relative volume, and attributes Friday's move to Saturday. The structure figures in this report were computed *after* de-duplicating and re-mapping the final row to its true session (Friday 2026-08-28); that mapping is corroborated independently, as external reporting puts BMW at €62.70 on 2026-08-28, up €3.14, matching the de-duplicated close of €62.64 against Thursday's €59.94.

Suggested fix, for a separate change: have `scanner/eu_history.py` stamp rows with the exchange session date rather than the run date, skip writes when the last session is already recorded, and reject any bar whose `open` falls outside `[low, high]`.
